The companion implementation for the paper — a clean two-system comparison. Pick any application, data type and channel — AWGN, Fading, simplified 3GPP-style or Simple NTN LEO — run the model and read off where each system passes its task, where the Current Smart system becomes unusable, and where the Auto switch changes over. The paper itself works its examples on the Simple NTN LEO channel, which is selected by default below.

Conventional codec

Current Smart system

Conventional coding, but already smart. Before transmitting, the device does local work and sends only what the task allows:

  • Label, intent or command code where a code is enough
  • An event code only when something changes (intermittent sensor)
  • A keyframe for surveillance — most of the content, where a code is not enough
Semantic codec

Semantic system

No separate compression step. The device extracts task-relevant features and maps them directly to channel symbols in one joint step:

  • “Semantic coder” for sensor, text, speech and control-type data
  • “DeepJSCC” only when the data is a Picture / image
  • No ARQ retries — it degrades gracefully instead of failing outright

Two systems, two codecs. Smart uses the conventional codec and Semantic uses the semantic codec. There are exactly two systems in this version, and those are the two names used everywhere below — in the controls, the charts, the tables and the downloads.

How Auto decides — Smart vs Semantic only

Step 1

Pass check

Task success at or above the Level 2 threshold and latency within budget. Thresholds: 90% for most types, 95% for intermittent, structured, surveillance and voice, 99% for control and keyword alert.

Step 2

Device-eligibility check

Semantic is only considered if the outdoor device can actually run a semantic encoder. Simple nodes that cannot are Smart-only, whatever the curves say.

Step 3

Gain check, after costs

If Semantic is the only system that passes, it is chosen. When both pass, Semantic must still win on channel symbols per successful task after a 15% complexity penalty and a 10% switching cost, by more than a 5% winning margin. These three are modelled parameters, not measurements.

Fallback

Keep Smart

If neither system passes, Auto does not force a choice: it keeps the Current Smart system as the default fallback. For control, Auto always chooses Smart.

Paper version — based on Harness v7. Simplified for the paper: two systems only (Current Smart system, Semantic system). All channels are playable — AWGN, Fading (Rayleigh and Rician), simplified 3GPP-style, and Simple NTN LEO at 550 km and 1,200 km (LEO only). The paper's worked examples — outdoor intermittent sensor, outdoor remote-site surveillance keyframe, and outdoor remote control on/off — use the Simple NTN LEO channel with outdoor devices.

Frontend cleanup 2026-10-30, using the frontend-design skill: system type, flat panels, larger touch targets, one delegated click handler. The model, channels, thresholds and Auto costs are unchanged from the paper version.

All numbers on this page come from the built-in modelled simulation (seeded, reproducible). They are simulated / modelled results, not measured encoder results, and not results from real hardware or a real satellite link.
